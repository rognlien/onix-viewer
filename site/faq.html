ONIX Viewer FAQ

Common questions about ONIX Viewer for Chrome, Firefox and Safari.

Why does Chrome show my local ONIX file as plain XML?

Chrome does not let any extension run on files opened from your disk (addresses starting with file://) until you allow it, one extension at a time. This is Chrome's rule, not a choice made by ONIX Viewer: an extension cannot ask for this access when it is installed, and it cannot turn it on by itself. Until you allow it, Chrome shows local files with its own XML view. Files opened from a web address are not affected.

How do I allow ONIX Viewer to open local files in Chrome?

  1. Open chrome://extensions in the address bar.
  2. Find ONIX Viewer and click Details.
  3. Turn on Allow access to file URLs.
  4. Reload any tab that already shows the file.

You only need to do this once. Chrome keeps the setting when the extension updates.

Is it safe to allow access to file URLs?

The setting lets ONIX Viewer read a local file when you open that file in a tab, the same way it reads an ONIX file from a web address. ONIX Viewer cannot list, open or read files on its own, has no background process, and sends nothing anywhere. The privacy policy describes this in full, and the source code is public.

Do I need this setting in Firefox?

No. Firefox has no such setting, and local ONIX files open in ONIX Viewer without one.

Can I use ONIX Viewer in Microsoft Edge?

Yes. ONIX Viewer is not listed in Microsoft's Edge Add-ons store, but Edge is built on Chromium and can install it from the Chrome Web Store. In Edge, turn on Allow extensions from other stores (Edge offers this on the Chrome Web Store page, or under edge://extensions), then open ONIX Viewer in the Chrome Web Store and click its install button. Brave, Opera and Vivaldi install it from the Chrome Web Store too.

For local files, Edge has the same Allow access to file URLs switch as Chrome, on the extension's details page in edge://extensions.

Edge reports itself to extensions the same way Chrome does, which is why the About window in Edge links to the Chrome Web Store.

Why does an ONIX file still show as raw XML?

ONIX Viewer takes over a page only when all of these are true:

  • The browser received the file as XML. A server that sends the file as plain text, or makes the browser download it, leaves nothing for the extension to take over. Download the file and open it from disk instead.
  • The file is ONIX: its root element is <ONIXMessage> or <ONIXmessage>, or it uses EDItEUR's ONIX namespace. Other XML is left to the browser on purpose.
  • In Chrome, for a file on your disk, access to file URLs is allowed.
  • In Safari, ONIX Viewer is turned on in Settings → Extensions and allowed on every website from its toolbar button.

A tab that was open before you installed or enabled the extension needs a reload.

Why does Safari not take over files opened from a web app?

Some web apps open a file in a new tab through a temporary blob: address. Safari does not run extensions on those addresses, so the file shows as raw XML there. Chrome and Firefox take these pages over. In Safari, download the file and open it instead.

Is there a size limit?

Files up to 500 MB open in the viewer. A larger file gets a notice instead, because a larger file can crash the tab.

Does ONIX Viewer send my files anywhere?

No. ONIX Viewer collects nothing, stores nothing and sends nothing. Its only network request fetches the page you are already viewing again, from the same address, to read the XML source. See the privacy policy.
